Система сповіщень (Alerts)

Система відстежує показники ECS-сервісу web1lab-service і надсилає повідомлення на електронну пошту, коли виконується умова тривоги.

Для реалізації використано:

Amazon CloudWatch — збирає та аналізує метрики, перевіряє умови тривоги.

CloudWatch Alarm — переходить у стан ALARM, коли задана умова виконується.

Amazon SNS — отримує повідомлення від CloudWatch і доставляє його підписникам.

Email subscription — забезпечує надсилання повідомлень на електронну пошту.

Адреса електронної пошти передається через змінну Terraform budget_email, оголошену у файлі terraform/variables.tf.

Підписка на SNS створюється у файлі terraform/alerts.tf.

Основна умова сповіщення — досягнення максимальної кількості ECS tasks:

Умова спрацювання: бажана кількість ECS tasks дорівнює або перевищує 4 протягом двох послідовних періодів по 60 секунд.

Коли умова виконується, CloudWatch переводить Alarm у стан ALARM та надсилає повідомлення через SNS.

Також є сповіщення коли високе використання CPU

Умова спрацювання: середнє використання CPU перевищує 70% протягом двох послідовних періодів по 60 секунд.

Надсилання та відновлення сповіщень

Для CloudWatch Alarm налаштовано два типи дій:

alarm_actions — надсилання повідомлення при переході тривоги у стан ALARM;

ok_actions — надсилання повідомлення після повернення тривоги у стан OK.

Під час практичної перевірки було отримано:

Повідомлення ALARM — ECS-сервіс досяг максимальної бажаної кількості 4 tasks.

Повідомлення OK — після зменшення навантаження кількість бажаних tasks знизилася до 3, і умова тривоги більше не виконувалася.
