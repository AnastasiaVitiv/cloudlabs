# Кешування за допомогою Redis

## Архітектура

Для кешування даних API використовується Redis 7,
розгорнутий як окремий ECS Fargate service
`web1lab-redis`.

Застосунок підключається до Redis через приватне
DNS-ім'я Cloud Map:

`redis.web1lab.local:6379`

Redis працює у приватній підмережі. Доступ до порту
6379 дозволений лише для Security Group застосунку.

Параметри підключення:
- REDIS_URL=redis://redis.web1lab.local:6379
- CACHE_TTL_SECONDS=45

## Стратегія кешування

Реалізовано Cache-Aside.

Під час GET-запиту:
1. Застосунок перевіряє наявність даних у Redis.
2. Якщо дані є, повертає їх із кешу (HIT).
3. Якщо даних немає, виконує запит до MySQL (MISS).
4. Отриману успішну відповідь записує в Redis.
5. Запис кешу автоматично закінчує дію через 45 секунд.

Кешування застосовується до GET-запитів API кораблів.

## Інвалідація кешу

Після успішного створення корабля через POST
застосунок збільшує версію кешу в Redis.

Версія використовується у ключах кешу. Тому наступні
GET-запити не використовують старі записи, а отримують
актуальні дані з бази та створюють нові записи кешу.

## Перевірка

Перевірено HTTP-заголовок `X-Cache`:

- MISS — дані відсутні в кеші;
- HIT — дані отримані з Redis;
- BYPASS — кешування пропущено;
- ERROR — під час роботи кешу виникла помилка.

Практично перевірено:
- перший GET повертає MISS;
- повторний GET повертає HIT;
- після 46 секунд кеш закінчує дію;
- після POST-запиту кеш інвалідується;
- наступний GET повертає MISS, а повторний — HIT.

## Результати k6

Під час навантажувального тестування отримано:

- Cache HIT: 12850.
- Cache MISS: 5429.
- HTTP-запитів: 20310.
- p95: 98.42 мс.
- Помилкових HTTP-запитів: 0%.

Частка HIT серед зафіксованих HIT і MISS становила
приблизно 70.3%.

## Порівняння підходів

| Критерій | Без кешу | З Redis |
|---|---|---|
| Джерело даних | MySQL | Redis або MySQL |
| Повторні читання | Запит до MySQL | Можливий HIT із Redis |
| TTL | Не застосовується | 45 секунд |
| Інвалідація | Не потрібна | Після POST |
| Спільний кеш між ECS tasks | Ні | Так |

Redis дозволяє зменшити кількість повторних
звернень до MySQL і прискорити читання даних.
