Для сервісу `web1lab-service` у кластері `web1lab-cluster`
налаштовано автоматичне масштабування ECS.

Параметри:
- Мінімальна кількість завдань: 1.
- Максимальна кількість завдань: 4.
- Масштабування вгору та вниз виконується автоматично.

Використовуються дві політики Target Tracking:
- ALBRequestCountPerTarget: цільове значення 600 запитів
  на ціль.
- ECSServiceAverageCPUUtilization: цільове завантаження CPU 50%.

Для політик задано періоди очікування перед наступним
масштабуванням: 60 секунд для масштабування вгору
та 180 секунд для масштабування вниз.

Тест реалізовано за допомогою k6 у файлі `loadtest/ships.js`.

Сценарій:
- 3 хвилини — поступове збільшення навантаження до 10 VU;
- 5 хвилин — стабільне навантаження 10 VU;
- 2 хвилини — зменшення до 1 VU;
- 3 хвилини — стабільне навантаження 1 VU;
- 30 секунд — завершення тесту.

Кожна ітерація виконує один POST-запит для створення корабля,
один GET-запит списку та вісім GET-запитів окремих кораблів.

Загальна тривалість: 13 хвилин 30 секунд.

## Результати навантажувального тесту

- Максимальна кількість VU: 10.
- Кількість ітерацій: 2031.
- Загальна кількість HTTP-запитів: 20310.
- Невдалі HTTP-запити: 0 (0%).
- Середній час відповіді: 37.75 мс.
- p95: 98.42 мс.
- p99: 131.89 мс.
- Cache HIT: 12850.
- Cache MISS: 5429.

## Перевірка масштабування

За історією ECS Application Auto Scaling підтверджено
автоматичну зміну кількості завдань.

Під час тестування кількість завдань збільшувалася
до 4, а після зменшення навантаження поступово
зменшувалася.

Усі перевірені операції масштабування завершилися
зі статусом Successful.

## CloudWatch Dashboard

Створено Dashboard `web1lab-dashboard`, який містить
п'ять графіків:

1. ECS Desired Tasks vs Running Tasks Count.
2. ECS CPU Utilization.
3. Requests per minute.
4. ALB Target Response Time (p95).
5. HTTP 5XX Errors.

## Сповіщення

Для надсилання повідомлень створено SNS topic
`web1lab-alerts`.

Основна умова сповіщення:
кількість бажаних ECS-завдань досягає 4 протягом
двох послідовних періодів по 60 секунд.

Для Alarm налаштовано AlarmActions та OKActions.

Додатково налаштовано сигналізацію, якщо CPU перевищує
70% протягом двох періодів по 60 секунд.
