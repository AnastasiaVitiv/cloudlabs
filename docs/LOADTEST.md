Для тестування використовується інструмент k6. Сценарій розміщений у файлі loadtest/ships.js.

Тест виконується через публічну адресу Application Load Balancer (ALB), який розподіляє запити між ECS tasks.

Сценарій тестування:

Кожен віртуальний користувач (VU) виконує одну ітерацію, яка складається з таких операцій:

POST-запит — створення нового корабля в базі даних.

GET-запит — отримання списку кораблів.

Вісім GET-запитів — отримання інформації про окремий корабель.

Пауза 2 секунди перед наступною ітерацією.

Таким чином, одна ітерація містить один запит на запис і дев'ять запитів на читання.

Для перевірки кешування додатково передбачено два режими:

enabled — кеш Redis використовується;

bypass — GET-запити обходять кеш за допомогою HTTP-заголовка X-Cache-Mode: bypass.

Параметри навантаження

За замовчуванням кількість віртуальних користувачів становить 10. Її можна змінювати через змінну середовища VUS.

Сценарій складається з п'яти етапів:

1. 3хв кількість VU поступово збільшується до 10

2. 5 хв кількість VU 10, стабільне навантаження

3. 2 хв поступово кількість VU зменшується до 1

4. 3 хв Завершення тесту

Загальна тривалість тесту — 13 хвилин 30 секунд.

Запуск тестування:

Команда запуску тесту з 10 віртуальними користувачами:

BASE_URL="$(terraform -chdir=terraform output -raw alb_dns_name)" VUS=10 CACHE_MODE=enabled k6 run loadtest/ships.js

Для збільшення кількості користувачів можна змінити VUS, наприклад на 20:

BASE_URL="$(terraform -chdir=terraform output -raw alb_dns_name)" VUS=20 CACHE_MODE=enabled k6 run --out json=loadtest/results-20vu.json loadtest/ships.js

Для тестування без використання кешу:

BASE_URL="$(terraform -chdir=terraform output -raw alb_dns_name)" VUS=20 CACHE_MODE=bypass k6 run loadtest/ships.js

BASE_URL — актуальна адреса балансувальника, VUS — кількість віртуальних користувачів, CACHE_MODE — режим роботи кешу.

Перевірка автоматичного масштабування:

Під час навантажувального тестування перевірено роботу Application Auto Scaling для ECS-сервісу web1lab-service.

Кількість ECS tasks автоматично збільшувалася відповідно до навантаження та досягала встановленого максимуму — 4 tasks.

Після зменшення навантаження кількість tasks поступово зменшувалася.
