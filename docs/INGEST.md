Приймання даних у чергу (Ingest)
Схема JSON-повідомлення
{
  "sensor_id": "sensor-temp-01",
  "sensor_type": "temperature",
  "value": 23.45,
  "unit": "C",
  "location": {
    "lat": 49.8397,
    "lon": 24.0297
  },
  "measured_at": "2026-11-21T20:00:00.123456+00:00"
}
Приклад запиту curl
curl -i -X POST "$API_URL/measurements" \
  -H "Content-Type: application/json" \
  -H "x-api-key: super-secret-iot-key-2026" \
  -d '{
    "sensor_id": "sensor-temp-01",
    "sensor_type": "temperature",
    "value": 24.8,
    "unit": "C",
    "location": {"lat": 49.8397, "lon": 24.0297},
    "measured_at": "2026-11-21T20:05:00Z"
  }'

  Чому приймач не обробляє дані сам, а лише складає їх у чергу?
Згладжування піків (Load Leveling / Backpressure): Датчики можуть надсилати тисячі запитів за секунду. Черга SQS поглинає сплеск трафіку, дозволяючи обробникам читати повідомлення у стабільному темпі без перевантаження бази даних.

Мінімальна затримка відповіді (Low Latency): Приймач повертає 202 Accepted одразу після запису в чергу, не змушуючи IoT-пристрій чекати завершення важких транзакцій БД.

Відмовостійкість (Decoupling): Якщо реляційна БД тимчасово недоступна або оновлюється, приймання даних не зупиняється — повідомлення безпечно накопичуються в черзі до відновлення роботи обробника.
